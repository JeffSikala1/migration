Core Principles

Finish-release plans must be:
	•	validation-first
	•	repo-aware
	•	artifact-aware
	•	idempotent (rerun-safe)

Do not:
	•	guess release branches
	•	assume repo structure
	•	assume integration branch (main may not exist)
	•	assume artifact layout
	•	treat cleanup as proof of release success
	•	treat ancestry re-proving failure as release failure

Always derive release branch from Maven version:

release/<version>

(strip -SNAPSHOT)

Final Release Pipeline Pattern

Two stages:
	1.	Promote Release Artifacts
	2.	Finalize Git Release

Resolve version using:

mvn help:evaluate -Dexpression=project.version -DforceStdout

Use a shared rerun-safe variable (e.g., bamboo_skip_release) injected across tasks to skip already-finalized work.

Git & Branch Rules

Do not assume main:
	•	may be develop, main, master, or repo-specific
	•	Bamboo checkout branch ≠ finalize target branch

Always validate:

Finalize must use actual integration branch—not assumptions.

Validation-First Rule

When uncertain, validate:
	•	Git refs, tags, release branch
	•	Artifactory paths, counts, coordinates
	•	artifact completeness
	•	release completion state

Use:
	•	Git: ls-remote, fetch, show-ref, rev-parse, merge-base
	•	Artifactory: AQL, GAVC

Structure:

validate → interpret → fix

Never guess when validation is possible.

Idempotency & Reruns

Plans must be rerun-safe.

Common real scenario:
	•	promote succeeds
	•	merge succeeds
	•	tag succeeds
	•	branch deleted
	•	rerun → ancestry cannot be reproven

This is NOT failure.

Reruns must tolerate:
	•	existing tag
	•	existing artifacts
	•	missing release branch
	•	already-merged state

⸻

Final-State Signals (Authoritative)

Treat release as complete if ALL are true:
	•	remote tag exists
	•	full expected artifacts exist in conexus-release-local
	•	release branch is absent or removable

If true:
	•	skip promote/finalize/cleanup
	•	do not fail due to ancestry checks

Final-state signals override ancestry re-proving limitations.

⸻

Cleanup Rules

Cleanup is NOT proof of release.

Cleanup must be:
	•	idempotent
	•	rerun-safe
	•	best-effort
	•	non-fatal

Do:
	•	validate tag exists
	•	fetch minimal refs
	•	delete local tag conflicts:

git tag -d <tag> || true

	•	attempt ancestry check (optional)
	•	attempt branch deletion

Do NOT:
	•	fail due to ancestry re-check failure
	•	treat cleanup as release validation
	•	fail if branch already deleted

If final-state signals exist:
	•	skip cleanup OR run best-effort only

Cleanup must never invalidate a confirmed release.

⸻

Git Finalization Behavior

Must be:
	•	defensive
	•	explicit
	•	repo-aware
	•	not overly strict

Do:
	•	fetch refs explicitly
	•	validate release branch
	•	validate integration branch
	•	check tag existence
	•	verify ancestry when possible
	•	treat “already up to date” / “no changes” as normal

Do NOT:
	•	rely on local workspace as truth
	•	assume checkout branch = target branch
	•	fail solely due to ancestry proof failure

Prefer multi-signal validation over single checks.

Artifact Awareness

Apps may be:
	•	multi-module
	•	multi-artifact
	•	mixed packaging (pom/jar/war/ear/tests)

Always validate:
	•	group path
	•	module structure
	•	version path
	•	expected artifact count
	•	classifiers

If Artifactory returns none:
	•	validate coordinates before assuming failure

If partial artifacts:
	•	treat as incomplete release
	•	fail and investigate

Proven Implementation Pattern

Promote
	•	validate SSH key
	•	generate Maven settings
	•	resolve version
	•	derive release branch
	•	validate release branch
	•	if missing → check final-state signals
	•	if true → skip
	•	validate artifact state:
	•	none → promote
	•	full → skip
	•	partial → fail
	•	run promote.py

Finalize
	•	resolve version again
	•	validate release state
	•	if final-state signals exist → skip
	•	validate integration branch
	•	merge release branch
	•	remove SNAPSHOT
	•	tag if needed
	•	push branch/tag
	•	treat no-op as success

Cleanup
	•	if skip flag → exit
	•	if finalized:
	•	skip OR best-effort delete branch
	•	never fail due to cleanup
