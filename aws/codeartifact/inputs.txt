Artifactory Retention Recommendations

* No retention policy exists today. Artifacts across CNXS repositories currently accumulate indefinitely, our clean scripts and Artifactory storage data did not identify an existing cleanup process for old artifacts.
* Prioritize conexus-snapshot-local. It currently represents 99.11 GB / 48,733 files which is about 26% of total storage and is growing by roughly 1,000 artifacts per week. Starting proposal: keep the last 10 builds per module/branch.
* Address Release and RC repositories next. conexus-release-local is the second largest repository at 25.88 GB / 3,299 files, while conexus-rc-local contains 4.31 GB / 2,561 files. Because Release and RC artifacts may be required for rollback or hotfix scenarios, starting proposal: keep the last 10 releases per release line and 10 RC builds per release line.
* Maven and plugin backup are lower priority. conexus-maven-local and conexus-plugins-backup account for less than 1.3 GB combined less than 1%. A lighter policy, such as the last 5 builds or 90 days, should be sufficient.
* Use native Artifactory cleanup if available. Confirm whether our current Artifactory version/license supports native cleanup policies before developing a custom AQL/script based solution. Any cleanup should first run in dry run/report only mode.
* Developer input needed before implementation. We still need to validate artifact download/usage frequency particularly for snapshots and confirm that the proposed retention counts provide enough history for rollback, troubleshooting, and development needs before enabling deletion.
