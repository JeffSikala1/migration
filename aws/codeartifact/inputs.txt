While digging through the JFrog docs, I found that for Artifactory 7.x the SAML ACS / Reply URL should be:

https://artifactory.mgmt.cnxs.vpcaas.fcs.gsa.gov/ui/api/v1/auth/saml/loginResponse/gsa-auth

not the older /artifactory/webapp/saml/loginResponse path used for older versions.

Also, JFrog’s docs say multiple SAML configurations are being rolled out to Cloud only, while this environment is self-hosted. I suspect we may be mixing the newer named-provider flow with a self-hosted backend that is not actually activating it the same way.






curl -k -u <admin_user>:<admin_pass> \
  https://artifactory.mgmt.cnxs.vpcaas.fcs.gsa.gov/access/api/v1/saml





curl -k -u <admin_user>:<admin_pass> \
  https://artifactory.mgmt.cnxs.vpcaas.fcs.gsa.gov/access/api/v1/saml/gsa-auth


curl -k -u <admin_user>:<admin_pass> \
  https://artifactory.mgmt.cnxs.vpcaas.fcs.gsa.gov/access/api/v1/saml/gsa-auth


curl -k -I \
  https://artifactory.mgmt.cnxs.vpcaas.fcs.gsa.gov/ui/api/v1/auth/saml/loginResponse/gsa-auth
