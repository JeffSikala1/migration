# EC2 Host Documentation — Atlassian Host (.34)

**Host:** `ip-10-56-112-34.ec2.internal` (`10.56.112.34`)
**Documented:** 2026-06-03

---

## Background / Why This Page Exists

During a routine patch cycle, this host was restarted and came back without the `/app` volume mounted. Because this volume hosts all Docker data (volumes, images, container layers), all Atlassian application data appeared missing until the root cause was identified and the volume was manually remounted. This page documents the current state of the host so that any future incident — patching, migration, rebuild, or unexplained outage — can be diagnosed and recovered quickly.

### 2.3 /etc/fstab (Current State)

```

UUID=E147-FCAD        /boot/efi       vfat    defaults,noatime,uid=0,gid=0,umask=0077,shortname=winnt,x-systemd.automount 0 2
tmpfs /dev/shm tmpfs defaults,nodev,noexec,nosuid 0 0
#/dev/nvme1n1 /var/lib/docker ext4 defaults 0 2   ← commented out (old path)
/dev/nvme1n1p1 /app xfs defaults 0 2               ← CRITICAL: Docker data volume
```

**Note:** The commented-out line `#/dev/nvme1n1 /var/lib/docker` reflects the original intended mount point before Docker root was relocated to `/app/docker`. The active entry `/dev/nvme1n1p1 /app` is what must survive any rebuild or restore. There is no entry for `/mnt/temp` (nvme2n1) — this volume is mounted at runtime and will not auto-mount on reboot.

### 2.4 Docker Root Directory

Docker's data root is configured to `/app/docker` (not the default `/var/lib/docker`). This is set in `/etc/docker/daemon.json`:

```json
{
  "data-root": "/app/docker",
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "5"
  }
}
```

Everything Docker manages — images, container layers (overlay2), named volumes — lives under `/app/docker/`. If `/app` is not mounted, none of it is accessible.
